### 브라우저 흐름

1. 최초 설정 → 홈 → 식단 추가·수정·다시 기록·삭제 → 운동 추가·수정 → 기록 완료 → 새로고침 → 목표·주기 변경 → 체중 기록 → 초기화 → 파일 백업 복원
2. 잘못된 백업 거부 → JSON 붙여넣기 → 누락 항목 안내 → 과거 날짜의 실제 0kcal 기록 확인
3. 320px·다크 시스템 설정에서도 흰 배경 유지 → 미완성 신체 입력 임시 저장 → 새로고침 후 복원
4. TDEE 재계산 → 오늘 잔고 보존 → 공식 SDK mock 파일 내보내기 → JSON 내용·이력 적용일 검사 → 재복원
5. 4개 탭의 라이트·다크 시스템 설정에서 흰 배경·초록 포인트, 글자 크기, 터치 영역, 가로 잘림, 활성 버튼의 4.5:1 색 대비
6. 모바일 터치 환경의 핀치 줌 차단, 입력 포커스 시 배율 유지, 한 손가락 스크롤 유지

스크린샷은 `test-results/`에 생성되며 Git 추적에서 제외합니다. 테스트 데이터는 독립된 브라우저 컨텍스트·메모리 저장소에만 사용하며 앱에 초기 데이터를 주입하지 않습니다.

## 실제 토스 앱에서 남은 확인

브라우저는 공식 devtools mock을 사용합니다. 아래 항목의 네이티브 동작은 아직 확인하지 않았습니다.

- iOS·Android 토스 앱에서 종료·재실행 후 SDK Storage 지속성
- WebView의 일반 JSON 파일 선택 및 읽기
- `File.saveBase64`의 실제 저장 위치와 취소·실패 동작
- 상단 뒤로가기, iOS swipe-back, 기기 Safe Area 및 모드 설정

일반 JSON 파일 선택·읽기 전용 공식 SDK API는 문서에서 확인되지 않았으므로 웹 표준 파일 입력과 JSON 붙여넣기로 구현했습니다. 파일 내보내기는 공식 API를 사용하며 Android 5.218.0+, iOS 5.216.0+가 필요합니다.

기존 콘솔 앱에 테스트 번들 업로드와 본인 테스트 푸시를 실행했습니다. 실제 기기에서 위 항목의 동작 확인이 필요하며, 검수 요청·출시는 실행하지 않았습니다.
