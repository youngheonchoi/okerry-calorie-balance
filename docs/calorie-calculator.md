# 칼로리 자동계산

광고 1회당 5회 충전, 유효기간 없음, 0회일 때만 다시 광고를 봅니다. 보상 SDK의 `userEarnedReward`에서만 충전을 요청합니다. 광고 닫기·취소·실패는 충전하지 않습니다.

음식명이 있을 때 자동계산 버튼이 활성화됩니다. 잔여 횟수는 빨간 숫자 배지에 표시합니다. 버튼을 누르면 매번 안내창에서 한 번 더 확인합니다. 취소는 왼쪽, 충전/계산하기는 오른쪽입니다. 광고를 마치면 계산 확인창으로 돌아가며 자동으로 계산하지 않습니다.

계산 순서는 Storage의 정확히 같은 음식명 첫 기록 → 전체 회원 foods 테이블의 정확히 같은 음식명 첫 id → OpenAI 음식명 추정입니다. 기존 무료 추천 목록 선택은 그대로 유지합니다. 수량을 곱하기 전 1개 기준 칼로리를 입력합니다. AI 결과에는 추정 안내를 표시합니다.

횟수는 서버 DB에서 관리하고, 계산 성공 시에만 차감합니다. AI가 `recognized: false`를 반환하면 0 kcal로 입력하고 1회 차감합니다. 통신 오류·잘못된 응답·refusal은 차감하지 않습니다. 예약 중 요청은 중복 실행하지 않으며 5분 뒤 해제합니다. 응답 유실 시 기기에 보관한 같은 계산 ID/보상 ID로 재확인하여 중복 차감·충전을 막습니다. 네트워크 오류를 음식 저장 화면의 오류로 표시하지 않습니다. 원문/키/음식명이 없는 안전한 오류 코드를 Storage 최대 20개에 보관했다가 다음 인증 요청 시 서버 로그로 보냅니다.

## 설정과 확인

- API: `OPENAI_API_KEY`(필수), `OPENAI_CALORIE_MODEL`(선택, 기본 gpt-6-luna), `TOSS_REWARDED_AD_GROUP_ID`(실제 광고 ID 발급 후).
- API 광고 ID가 없으면 새 충전을 차단합니다. 임의 테스트 보상이나 인증 우회는 없습니다.
- 테스트는 **격리된 테스트 DB와 API 배포**에 `TOSS_REWARDED_AD_GROUP_ID=ait-ad-test-rewarded-id`를 설정합니다. 미니앱 `npm run dev`는 공식 테스트 광고 ID를 사용합니다. QR 테스트 번들은 `VITE_TOSS_REWARDED_AD_GROUP_ID=ait-ad-test-rewarded-id`로 빌드할 수 있습니다. 테스트 설정을 운영에 사용하지 않습니다.
- 미니앱 API 주소는 `VITE_CALORIE_API_URL`로 변경할 수 있습니다. 기본은 기존 Vercel API입니다. 브라우저 SDK mock 인증은 실제 서버에서 거부되므로 정상 인증/광고/AI는 Toss 실기기에서 확인해야 합니다.
- Vercel 변수 변경 후 API 재배포가 필요합니다. 코드 반영과 재배포 전까지 기존 운영 API는 변하지 않습니다.
- DB 스키마는 API 프로젝트 `database/calorie-credits.sql` 참고. 사용자에게 이미 제공한 테이블 구조를 사용합니다.

## 검증 범위와 제한

단위 테스트는 조회 우선순위, 실패 시 미차감, 중복 요청 재사용, 인증과 설정 누락, AI JSON 검증, 광고 보상/닫기 구분, SDK 해제를 확인합니다. 브라우저 테스트는 가짜 API 응답으로 안내창과 배지/입력 반영을 확인합니다. 실제 유료 AI 호출·실제 광고 시청·운영 DB 갱신은 테스트하지 않았습니다.

광고 SDK 콜백은 서버가 독립적으로 시청을 증명하는 서명된 영수증이 아닙니다. 인증·보상 세션 소유권·중복 지급·횟수 검사는 있지만 조작된 인증 클라이언트의 거짓 complete 요청까지 차단하지는 못합니다. 서버 검증 방식(SSV) 지원은 광고 사업자와 별도로 확인해야 합니다. Storage 후보 칼로리 역시 사용자 입력으로 취급합니다.
